# Дашборды Виферон

Два статических дашборда в одном проекте Cloudflare Pages. Данные лежат в Google
Таблицах, забираются через прослойку на Cloudflare, отображаются без серверного
рендеринга и без внешних библиотек.

| Страница | Адрес | О чём |
|---|---|---|
| Отзывы | `/` | карточки товара на аптечных сайтах и отзовиках |
| Медиамониторинг | `/media/` | упоминания и тональность Виферона на фоне конкурентов |

**Живая цепочка данных:** Google Таблица → Cloudflare Pages Function
(`/api/reviews` или `/api/media`) → браузер.

## Дашборд отзывов — что показывает

| Блок | Что отвечает |
|---|---|
| KPI-строка | всего отзывов, площадок, карточек, карточек без отзывов, медиана |
| Отзывы по площадкам | где сосредоточена масса отзывов; точка у подписи — тип площадки |
| Отзывы по форме выпуска | суппозитории разбиты по дозировкам, отдельно мазь, гель и брендовые карточки |
| Где живут отзывы | доля аптечных сайтов против отзовиков и форумов |
| Покрытие: площадка × форма | тепловая карта; видно и «ноль отзывов», и «карточка вообще не отслеживается» |
| Таблица | все строки с фильтрами, сортировкой, ссылками и выгрузкой в CSV |

Фильтры (поиск, тип площадки, площадка, форма выпуска, «только без отзывов»)
пересчитывают **всё**, что ниже них, включая KPI и графики.

## Дашборд медиамониторинга — что показывает

| Блок | Что отвечает |
|---|---|
| KPI-строка | упоминания Виферона, доля голоса, место в рейтинге, индекс лояльности, негатив — всё с изменением к прошлому периоду |
| Доля голоса | гантели «прошлый период → отчётный» по 14 брендам, отдельно по упоминаниям, позитиву и негативу |
| Тональность | расходящаяся стопка: негатив влево, позитив вправо, нейтраль по центру |
| Индекс лояльности | сколько позитивных упоминаний приходится на одно негативное |
| Динамика Виферона | помесячно с 2016 года: упоминания, позитив, негатив, лояльность, консультанты |
| Виферон против конкурентов | линии по месяцам или годам, в абсолюте или в доле голоса; можно подсветить одного конкурента |
| KPI по годам | в количестве и в коэффициенте, с разбивкой по кварталам в подсказке |
| Активность и бан-контроль | посты, комментарии, репосты по годам; заблокированные аккаунты по месяцам |
| Таблица | все бренды отчётного периода с сортировкой и выгрузкой в CSV |

Оба дашборда подхватывают тему системы, имеют переключатель светлая/тёмная и раз
в 5 минут тихо обновляют данные.

## Структура

```
public/
  index.html               дашборд отзывов
  assets/styles.css        токены тем и общие компоненты обоих дашбордов
  assets/common.js         форматирование, тултип, тема, загрузка данных
  assets/app.js            логика дашборда отзывов
  media/index.html         дашборд медиамониторинга
  media/assets/app.js      логика медиадашборда, включая линейные графики
  assets/media.css         компоненты, которые есть только у медиадашборда
  data/fallback.json       снапшот таблицы отзывов
  data/media.json          снапшот таблицы медиамониторинга
functions/
  api/reviews.js           прослойка к таблице отзывов
  api/media.js             прослойка к таблице медиамониторинга
lib/
  sheets.js                общий доступ к gviz, edge-кэш, формирование ответа
scripts/
  snapshot.mjs             обновление снапшотов (переиспользует код функций)
wrangler.toml              конфиг Pages: каталог сборки и переменные
```

## Как работает прослойка

Обе функции построены на общем модуле `lib/sheets.js` и работают одинаково:

1. Ходит в `gviz/tq` Google Таблиц и приводит ответ к стабильной JSON-схеме
   (`{ ok, source, sheet, fetchedAt, count, rows[] }`).
2. Кэширует ответ на edge Cloudflare — Google отдаёт `no-store`, поэтому TTL
   держим сами (`CACHE_TTL`, по умолчанию 300 секунд).
3. Отдельно хранит **последний удачный ответ**. Если Google лёг, отдаётся он
   с заголовком `x-cache: STALE` — дашборд не белеет, а честно пишет об этом.
4. Не пускает ID таблицы в браузер: фронтенд знает только про `/api/reviews`.

Полезные заголовки ответа: `x-cache` (`HIT` / `MISS` / `BYPASS` / `STALE`) и
`x-data-source`. Принудительно обновить: `?refresh=1` — это же делает кнопка
«Обновить».

Если прослойка недоступна (например, открыли `public/` как статику), дашборд
загружает снапшот из `data/` и показывает баннер о том, что данные снапшотные.

Таблица медиамониторинга сложнее: у листов многоуровневые шапки, а на одном листе
рядом лежит несколько блоков, поэтому `functions/api/media.js` берёт каждый блок
точным диапазоном. Две вещи, о которые легко споткнуться при правках:

* **Названия листов должны совпадать с ярлыками вкладок символ в символ.** Если
  имя не найдено, gviz не отдаёт ошибку, а молча возвращает первый лист таблицы.
  Разбор проверяет, что среди брендов есть Виферон, и падает с внятной ошибкой,
  если пришло не то.
* **Выгрузка в xlsx режет названия листов до 31 символа** — «Аналитика год к году
  перевернуто» превращается в «…перевернут». Сверяться нужно с ярлыком вкладки.

## Требования к Google Таблице

* Доступ: «Любой, у кого есть ссылка — читатель». Ничего публиковать в веб
  отдельно не нужно, `gviz` работает по этому же доступу.
* Первая строка — заголовки. Колонки определяются по названию, порядок и
  формулировки могут меняться:

| Поле JSON | Как ищется в заголовке |
|---|---|
| `url` | `ссыл`, `url`, `link` |
| `reviews` | `отзыв` |
| `status` | `статус`, `примеч`, `коммент` |
| `n` | `№`, `номер`, `#` |
| `site` | `сайт`, `площад`, `домен` |
| `product` | `sku`, `товар`, `продукт`, `позиц` |

Если заголовок не распознан, поле берётся по позиции колонки (A…F). Строки без
площадки и без названия товара пропускаются.

## Деплой на Cloudflare Pages

Пошаговая инструкция со всеми настройками, подключением поддомена, закрытием
доступа и диагностикой — в **[DEPLOY.md](DEPLOY.md)**. Коротко:

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git**, выбрать этот репозиторий.
2. Настройки сборки:
   * Framework preset — **None**
   * Build command — оставить пустым
   * Build output directory — **`public`**
3. Deploy. Каталог `functions/` Cloudflare подхватывает сам — `/api/reviews`
   появится без дополнительной настройки.

Переменные `SHEET_ID`, `SHEET_NAME`, `MEDIA_SHEET_ID` и `CACHE_TTL` заданы в
`wrangler.toml`.
Для Pages этот файл — источник истины: в дашборде переменные видно, но
редактировать их нельзя. Чтобы управлять ими из интерфейса, удалите блок
`[vars]` и задайте значения в **Settings → Variables and Secrets** отдельно для
Production и Preview.

Разовый деплой из командной строки:

```bash
npm install
npx wrangler pages deploy public
```

Домен подключается в **Custom domains** проекта. Дашборд внутренний — закройте
его **Cloudflare Access**; в разметке уже стоит `noindex, nofollow`.

## Локальная разработка

```bash
npm install
npm run dev          # wrangler pages dev public → http://localhost:8788
```

`wrangler pages dev` поднимает и статику, и функцию, поэтому `/api/reviews`
работает локально ровно так же, как в проде.

Без wrangler можно открыть просто статику (`npx serve public`) — дашборд
переключится на снапшот и покажет об этом баннер.

Обновить снапшоты:

```bash
npm run snapshot          # оба
npm run snapshot media    # только медиамониторинг
```

## Настройка под себя

* **Список отзовиков** — `REVIEW_PLATFORMS` в `public/assets/app.js`. Всё, чего
  нет в списке, считается аптечным сайтом или e-com.
* **Формы выпуска и дозировки** — `classifyForm`, `classifyDose`,
  `CATEGORY_ORDER` там же. Строки таблицы разбираются по тексту, так что
  «Супп. 150тыс МЕ», «Супп. 150 000 МЕ» и «свечи 150000» попадут в одну корзину.
* **Пороги тепловой карты** — `HEAT_BINS`. Шаги неравномерные, потому что
  распределение отзывов длиннохвостое: от 0 до 1000+.
* **Частота автообновления** — `CONFIG.autoRefreshMs` в `app.js` каждой страницы.
* **Блоки медиадашборда** — массив `BLOCKS` в `functions/api/media.js`: лист и
  диапазон каждого куска данных. Диапазон всегда начинается со строки шапки.
* **Палитра** — CSS-переменные в начале `public/assets/styles.css`. Категориальные
  цвета проверены на различимость при дальтонизме в обеих темах; тепловая карта
  использует одну голубую шкалу (на тёмной теме она развёрнута, чтобы «больше»
  оставалось заметнее фона).
